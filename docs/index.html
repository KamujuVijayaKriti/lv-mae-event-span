Event-Span Masking for Self-Supervised Long-Video Representation Learning and Violence Classification

A system that watches a long video and tells you what kind of event it contains: Normal, Fighting, Shooting, Riot, Abuse, Car accident or Explosion.

Problem statement

Long, untrimmed videos such as CCTV and movie footage can run for minutes or hours, while the event that decides what the video is about (a fight, a shooting, a crash) may last only a few seconds. Labelling such videos by hand is slow and costly, so a model must learn mostly from unlabelled videos, and it must understand whole events, not single moments, to classify a long video correctly.

20 seconds that matter
0:001:00:002:00:00
Objective
  • Learn from long, unlabelled videos with LV-MAE self-supervised pretraining.
  • During pretraining, find the events in each video and hide whole, distinctive events, so the model learns what happens in a scene.
  • Classify each long video into one of 7 categories.
Result
87.73%test accuracy on XD-Violence, 7 classes

About 88 of every 100 test videos the system had never seen were given the right category (799 test videos).

Methodology

Pipeline of the project

Two stages. Stage 1 pretrains the encoder on unlabelled videos. Stage 2 freezes it and trains a small classifier on top.

Feature extraction

LanguageBind-Video-Huge-V1.5-FT reads 8 frames from each 5-s segment and outputs a 1024-d, L2-normalised embedding.

Event-span masking

Splits each video into events and hides whole, distinctive events. No trainable parameters.

LV-MAE

Transformer encoder (32 layers, 16 heads) and decoder (8 layers, 512-d). Loss is MSE on the hidden segment embeddings.

Attentive probe

An attention-pooling classifier on the frozen encoder, trained for 60 epochs on video-level labels.

Five steps from segment embeddings to a mask

1

Change detection

For each segment, measure how different it is from the segment just before it. Small means the two show the same thing; large means the scene changed.

s_i = 1 − cos(e_i, e_(i−1)), s_1 = 0
ScoreComparescossᵢ
s₂, s₃walk → walk0.800.20
s₄walk → fight0.001.00
s₅fight → fight0.980.02
s₆fight → fight0.960.04
s₇fight → walk−0.141.14
s₈walk → walk0.800.20

Example for s₄: e₃ · e₄ = 0.05 + 0.35 − 0.05 − 0.35 = 0, so s₄ = 1 − 0 = 1.00.

Why this step
  • It reduces 1024 numbers per segment to one "how much changed" value.
  • The value stays small inside an action and spikes where one action ends and the next begins (segments 4 and 7).
  • This finds action boundaries without anyone marking start and end times.
2

Event segmentation

Compute a threshold from the video's own scores. A segment starts a new event when its score is above the threshold and it is at least 2 segments after the previous boundary.

θ = mean(s) + 0.5 · std(s) (using s₂ … s_L) boundary at i if s_i > θ and i − b ≥ 2

mean = 2.80 / 7 = 0.400 · std = √(1.302 / 6) = 0.466
θ = 0.400 + 0.5 × 0.466 = 0.633

s₄ = 1.00 > 0.633 and s₇ = 1.14 > 0.633, so boundaries are at segments 4 and 7.

E1 = {1, 2, 3} walking · E2 = {4, 5, 6} fight · E3 = {7, 8} walking

Why this step
  • Events are the unit that gets hidden, so the method needs to know where each action starts and ends.
  • The threshold adapts to each video: shaky footage with high scores everywhere gets a higher bar, still footage a lower one.
  • The 2-segment gap stops a single noisy segment from becoming an event of its own.
3

Event distinctiveness

Average the embeddings inside each event and across the whole video, measure how far each event is from the video average, then convert those values to z-scores.

ē_k = mean(e_i : i ∈ E_k) ē = mean(e_1 … e_L) d_k = 1 − cos(ē_k, ē) z_k = (d_k − mean(d)) / std(d)
Eventē_kd_kz_k
E1 walk[0.57, 0.37, 0.57, 0.37]0.153−0.58
E2 fight[0.03, 0.70, −0.03, −0.70]0.470+1.155
E3 walk[0.60, 0.30, 0.60, 0.30]0.154−0.57

Video average ē = [0.375, 0.475, 0.350, −0.050]. The fight is furthest from it.

Why this step
  • An event that looks like the rest of the video (the walking) can be rebuilt by copying other visible parts, so the model learns little from it.
  • An event unlike the rest (the fight) has nothing similar left visible; rebuilding it requires understanding the context.
  • The z-score keeps only how much each event stands out within its own video, so the temperature in step 4 works the same way for every video.
4

Event sampling

Turn the z-scores into probabilities with a temperature τ, then draw a random order of events with Gumbel-top-k. τ falls during training.

τ(epoch) = 0.25 + 0.875 · (1 + cos(π · epoch / 150)) p_k = softmax(z_k / τ) g_k = −log(−log U_k), U_k ~ Uniform(0, 1) order = sort events by z_k / τ + g_k, largest first

At epoch 75 with U = (0.40, 0.55, 0.70): g = (0.09, 0.51, 1.03), keys = (−0.43, 1.54, 0.52), so the order is E2 → E3 → E1.

Why this step
  • The choice is random but weighted, so each epoch gives a different mask and the model cannot memorise one fixed puzzle per video.
  • Early training (τ = 2.0) still hides the other events often, so the model learns the whole video; late training (τ = 0.25) concentrates on the most distinctive event.
  • Gumbel-top-k gives a full ranking in one step, which step 5 walks through until the mask budget is used.
5

Whole-event masking

Hide events in the sampled order until half of the segments are hidden. An event that fits is hidden completely; if only part fits, a continuous piece of it is hidden. No event may take more than 40% of the video.

N_mask = L − ⌊0.5 · L⌋ cap = round(0.4 · L) take_k = min(|E_k|, still needed, cap)

L = 8, so N_mask = 4 and cap = round(3.2) = 3.

OrderEventNeededTakeHidden
1stE2 fight (3)434, 5, 6
2ndE3 walk (2)117
3rdE10–budget used
Why this step
  • Hiding a whole event leaves no visible piece of that action to copy from.
  • Partial events are hidden as one continuous piece, never as scattered single segments.
  • The 40% cap keeps enough of the video visible to rebuild a very long event.

What LV-MAE does with the mask

Encoder

Receives only the visible segments, here 1, 2, 3 and 8, with their position embeddings.

Decoder

Inserts mask tokens at the hidden positions 4, 5, 6 and 7 and predicts a 1024-d embedding for each.

Loss

Mean squared error between predicted and true embeddings, on hidden segments only.

Videos shorter than 8 segments use a fallback that hides single segments chosen by change score with the same Gumbel sampling. XD-Violence videos average about 33 segments.

Dataset

XD-Violence

A large dataset of untrimmed videos of violent and normal events, collected from movies and in-the-wild videos on YouTube (Wu et al., ECCV 2020).

What is in it

Videos come from movies, sports, games, cartoons, news, CCTV, hand-held cameras and car dashcams. 2,405 videos contain violence and 2,349 are non-violent.

NormalFightingShootingRiotAbuseCar accidentExplosion

Labels

Each video's category is written in its file name, for example …_label_B1-0-0 for Fighting. A violent video can carry up to 3 labels; this project uses the first, most important one. Training videos have video-level labels only.
